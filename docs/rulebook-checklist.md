# Rulebook checklist

How this build measures up against the coding rulebook it was built under (Foundry, *The Book of Coding Secrets*). The declared scope is in section 13 of `docs/superpowers/specs/2026-10-01-prediction-bench-design.md`.

Written 2026-10-07, at the end of the build, by reading each chapter's rules and then checking the repository against them. It is a self-assessment, so the weak spots are listed as findings (section 3) rather than hidden.

## 1. Scope and how it was checked

Project kinds: `site` and `data-pipeline`. Declared capabilities: `has-ui`, `has-routes`, `ships-client-bundle`, `is-deployed`, `has-third-party-deps`, `calls-external-apis`, `runs-background-jobs`, `has-persistent-state`, `costs-money-to-run`, `sends-push-notifications`.

Status words: **applied** (the rules were checked and the build meets them), **partial** (met in part; the gap is a numbered finding in section 3), **waived** (deliberately out of scope, with the reason), **n/a** (the rule's trigger does not exist in this project).

What the checking was, and its limits:

- **Read in full:** chapters 1 to 12, 14 to 16, 18, 21, 24, 37 and 40.
- **Read in part:** chapter 29 (intro, rules 1, 2, 4, 13, 16 and the rule list), 17, 19, 23, 25, 28, 30, 31, 34, 35, 36, 43 and 44 (the Do/Don't tables, plus the full text of the rules that touch this project: 19.1, 19.2, 19.4, 30.1, 30.2, 30.5, 30.17, 31.1 to 31.3, 34.1 to 34.4, 34.6, 34.8, 35.5, 35.6, 35.8, 36.1, 36.8, 36.10, 43.1, 43.4). Anything the table-only reading could not settle is marked as such.
- **The book's own checking tools were not run** (they need headless Chrome, the Foundry repository and, for some, network access). Where a rule is mechanical I checked it by hand or by a one-off measurement, and the evidence column says which. These are the measurements: the dashboard was opened with the 364-day backtest data in the in-app browser and measured at 320 CSS px width (no sideways scroll: `scrollWidth` 320; nothing overflows outside the scroll boxes it is meant to use), contrast ratios were computed from the stylesheet's colour tokens, computed styles (`color-scheme`, `text-wrap`, `font-variant-numeric`, `content-visibility`) were read from the live page, and the line length was measured in characters.
- **Tests run for this checklist:** the full Python suite (150 passed, then 150 passed again with the test files in reverse order), the 13 dashboard unit tests, `scripts/verify_data.py` ("data checks passed"), and the new capability-drift tests (4 passed; each was also broken on purpose, see chapter 31).

## 4. Capability drift

The rulebook's rule: a capability used but not declared is a finding. `tests/test_capabilities.py` detects the ones this project deliberately does not have, and passes:

- the site references no URL except the SVG namespace (no third-party requests, no fonts, scripts or analytics);
- the site never sets cookies;
- the site has no images, audio, video, forms or inputs;
- no topic-shaped ntfy URL appears in `bench/*.py`, the workflows or `assets.yaml`.

By reading the code, the declared capabilities match what the project does: it calls external APIs (yfinance, ntfy), runs background jobs (the scheduled workflows), keeps persistent state (files in `data/`), ships a client (a few static files), and sends push notifications. `localStorage` is used for two display preferences (mode, palette): that is browser storage, not a declared capability, and is noted here so it is not a surprise. Nothing undeclared was found.

Clean-clone run (chapter 34.1), 2026-10-07: the repository was cloned into an empty folder and the README's setup block was followed as written (virtual environment, `pip install -r requirements-dev.txt`, then the three test commands): 150 Python tests passed, 13 dashboard tests passed, and `scripts/verify_data.py data` printed "data checks passed". Run with Python 3.12 on Windows; the workflows use 3.12 on Linux.
