# neural_candlestick (dropped)
- Source: https://github.com/Gab0/neural-candlestick, "A python backend to predict prices of candlesticks". Spiked at commit `e70b2c6496343d2b43f1b4fefaa49423acb3b649` (master, the newest commit, dated 2019-02-28; the repo has seen no change since 2019, not 2024).
- Licence: MIT (`gh api repos/Gab0/neural-candlestick/license`, SPDX `MIT`, `LICENSE` in the tree). Licence is not the problem.
- Original code or reimplementation: would have been original third-party code. Not included, no reimplementation (the rules forbid copying its code, and its idea, an LSTM/Conv network on candle windows, is already covered by our own `lstm` estimator).
- Installs on a clean GitHub runner: no. Evidence from the spike (clone in a scratch directory, `pip install --dry-run` against the repo `.venv`, Python 3.12.10, torch 2.8.0, numpy 2.5.3; nothing was installed, `pip freeze` unchanged):
  - It is not a package: no `setup.py`, no `pyproject.toml`. It is a Flask server (`nc-server.py`) plus a CLI client (`nc-client.py`) meant to be driven over HTTP by a Gekko trading-bot indicator (`nncandle.js`, `neuralloader.js`). There is no function that takes a window of OHLC and returns a next-day close; `pip` cannot depend on it by commit, only a copy of its source tree could be used, which is not allowed.
  - Its `requirements.txt` pins `numpy==1.14.5`, `Flask==1.0.2`, `matplotlib==2.2.3`, `requests==2.19.1`, `keras==2.2.2`, `neat==0.4.1`, plus unpinned `theano`. `pip install numpy==1.14.5` fails on our Python 3.12 (the 2018 source tree does not build), and the repo's own pin is numpy 2.5.3 shared with Kronos, TimesFM and Chronos, so these pins cannot coexist with ours. Keras 2.2.2 alone resolves (with h5py), but it needs a Theano or TensorFlow 1.x backend that does not exist for this stack (`from keras.utils.generic_utils import ...` and `keras.backend.tensorflow_backend` are used), and `neat` and the DEvol fork (README: "compatible with python 3.7") are not on PyPI.
  - It ships no trained weights. The network is built from `defaultNetwork.json` (an architecture description) and trained at run time, or evolved with DEvol, on the shipped datasets `candles` (6,048,772 bytes) and `evalcandles` (1,145,069 bytes): nested arrays of OHLCV for one crypto pair with 5 columns (prices near 0.048), exported from Gekko, with no source, exchange, date range or licence stated beyond the repository's MIT licence. Training is slow, seeded nowhere in a way we could rely on, and covers a different asset and timeframe from ours.
- Spike result: could not be run. Nothing to time: the dependency stack does not install and the code has no callable prediction entry point.
- Decision: drop, because it cannot be depended on by pinned reference (not a package), its 2019 dependency pins cannot be installed beside our pinned stack without breaking the Kronos, TimesFM and Chronos pins or the Python version, it has no entry point for window-in, return-out and no shipped weights, and getting a result would mean copying and porting its code, which the rules forbid. No registry entry and no requirements file were added. The "optimistic backtest" caveat does not apply because nothing was run.
