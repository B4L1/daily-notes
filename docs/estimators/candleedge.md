# candleedge (dropped)
- Source: https://github.com/michaelsboost/CandleEdge, "Open-source candlestick pattern scanner and market structure analyzer". Spiked at commit `75761e26b23ccaf59b31365e1ec817374673d77b` (main, 2026-05-25).
- Licence: MIT (`gh api repos/michaelsboost/CandleEdge/license`, SPDX `MIT`, `LICENSE` reads "Copyright (c) 2026 Michael Schwartz"). Licence is not the problem.
- Original code or reimplementation: would have been original third-party code. Not included. We do not reimplement its patterns: our `candle_rules` (hammer, shooting star, engulfing) and `analog` (historical pattern matching, the same idea as its probability tables) estimators already cover that ground.
- Installs on a clean GitHub runner: not applicable. It is a browser application (HTML, Tailwind and Alpine.js, PWA with a service worker), not a library or a CLI, and not published on PyPI or npm.
- Spike evidence (clone in a scratch directory, Node v25.9.0, nothing installed into the repo):
  - `package.json` has only build scripts (rollup, postcss, an http-server for the page). There is no `main`, no `export`: `grep -c "export " src/script.js` gives 0. The 1,547 line `src/script.js` is one Alpine component, `Alpine.data('tradingDashboard', ...)`, registered inside `document.addEventListener('alpine:init', ...)`. Importing it in Node fails at once with `ReferenceError: document is not defined`. To call its pattern engine from Python we would have to extract its functions out of the component (copying its code) or drive it through a headless browser.
  - It does not produce a next-day signal. Its own `README.md` and `docs/model-notes.md` state it "does not attempt to predict the future", has "no machine learning" and "no AI-generated trading signals", and is purely descriptive: for each detected pattern it reports the historical share of positive forward returns and mean and median move after 3, 5, 10 and 20 candles, for a dataset the user loads (a CSV, shipped example `csv/NQ=F_data.csv`, 34 KB) or live crypto candles fetched from `api.exchange.coinbase.com` in the browser. There is no output that says "tomorrow's return is X"; turning its tables into one is our own design, which is what `analog` already is.
- Spike result: not runnable from Python without a browser, so there are no seconds per asset to report. Not timed.
- Decision: drop, because it cannot be integrated cleanly by pinned reference (a browser tool with no importable module and no CLI), it yields no next-day signal of its own, and the only route to one is copying or reimplementing its patterns, which the rules forbid and `candle_rules` and `analog` already make unnecessary. No registry entry and no requirements file were added. `analog` stays as our CandleEdge-style comparison. The "optimistic backtest" caveat does not apply because nothing was run.
