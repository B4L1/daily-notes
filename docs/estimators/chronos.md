# chronos
- Source: Amazon Science Chronos, "Chronos: Learning the Language of Time Series" (https://github.com/amazon-science/chronos-forecasting, paper arXiv 2403.07815). Code installed from PyPI, pinned `chronos-forecasting==2.3.2`, with `transformers==4.53.3` and `accelerate==1.8.1` (chosen so that `huggingface_hub==0.33.1` and `safetensors==0.6.2` stay as pinned for Kronos and TimesFM; transformers 5.x would force huggingface_hub 1.x).
- Licence, code: Apache-2.0 (`gh api repos/amazon-science/chronos-forecasting/license`, SPDX `Apache-2.0`; PyPI metadata also Apache-2.0).
- Licence, weights: official org `amazon`, repo `amazon/chronos-bolt-tiny`, model card metadata `license: apache-2.0` (https://huggingface.co/amazon/chronos-bolt-tiny). All four Bolt cards and chronos-t5-tiny carry the same licence. Chronos-2 (`amazon/chronos-2`) was not used (larger, and its card was not reviewed for this note).
- Checkpoint choice: Chronos-Bolt Tiny (9M parameters) is the smallest official CPU-friendly checkpoint that is also deterministic by construction. It is the same size class as the original `chronos-t5-tiny` (8M, 33.6 MB), but Bolt decodes quantiles directly instead of sampling token paths, and the README says Bolt is more accurate and up to 250x faster at equal size. Mini (85 MB) and Small (191 MB) exist if a larger model is wanted later.
- Weights: revision `a0e552de83495b5c28c14c71c374f3e33280b340`, `model.safetensors` 34,622,352 bytes (about 35 MB) plus `config.json` (1,120 bytes). sha256 of `model.safetensors` (`75068728d376d2bec670379eeef4bfb4d24c0cfe24d957451f8d19b447030a32`) is hardcoded in `estimators/chronos/fetch_assets.py` and checked at setup and before every load. safetensors only, no pickle. Stored in `data/cache/chronos_weights` (git-ignored, CI-cached). Only the official `amazon` org is contacted, and only by `python -m bench.cli setup --estimator chronos`.
- Original code or reimplementation: original third-party model wrapped by our own `ClosesForecaster` subclass. Registry `kind: pretrained`, `original_code: True`.
- Installs on a clean GitHub runner: yes, CPU only. `pip install -r estimators/chronos/requirements.txt`, then `setup` fetches the weights. In the repo `.venv` the install added accelerate, chronos-forecasting, psutil, regex, tokenizers and transformers; torch, numpy, huggingface_hub, safetensors, einops and the Kronos and TimesFM packages did not change, and `pip check` is clean. `predict` never touches the network: it loads from the local directory with `local_files_only=True` and `HF_HUB_OFFLINE=1`, and raises ImportError if the weights are missing or altered. The workflows already run predict and backfill with `HF_HUB_OFFLINE=1` and cache `data/cache` keyed on this estimator's `fetch_assets.py`, so no workflow change was needed.
- What the model does: a T5 encoder-decoder that patches the context and directly emits quantile forecasts across the horizon, pretrained on about 100 billion observations (per its card). We feed the last 512 closes of one asset, take the 0.5 quantile (median) for 5 steps, use close 1 relative to the last close as `expected_return` and store all 5 closes as the path. The model only sees closes.
- Determinism: no sampling on this path. Three consecutive passes over six real assets returned exactly equal predictions (including the stored floats), and the contract test (two calls) passes.
- Spike result (16 CPU Windows machine, 4 torch threads): model load 13 s once, then about 0.03 s per asset-day steady state. A 30 day replay (stride 1, 30 prediction days, 21 assets, scratch directory) took 36 s including load, 0 failed days. Projected: daily run about 1 s of compute for 21 assets, a one-year stride 1 backfill about 4 to 5 min locally and perhaps 10 to 20 min on a 2 to 4 CPU runner, far inside the 340 minute backfill budget and the 45 minute daily timeout. No `backfill_stride` is needed (default 1).
- Local verification: 30 day replay in a scratch directory, 0 failed days, `scripts/verify_data.py` passed. No backtest data is committed; the full replay is meant to run in the cloud backfill workflow.
- Caveat: the backtest may be optimistic. Chronos was pretrained on a large corpus of public series (including financial and exchange-rate data in the paper's benchmark sets) whose cut-off is before the replayed year only as far as the card states, and the card does not enumerate every source, so leakage cannot be excluded. Only the daily live predictions are a fair out-of-sample test. Floating-point results can differ slightly across CPUs and thread counts, so a regenerated backtest may differ in the last digits; committed predictions are kept by the keep-existing rule.
- Decision: include (stride 1), because the code (Apache-2.0) and the Bolt Tiny weights (Apache-2.0) allow it, it installs and runs on CPU without disturbing the other estimators' pins, is deterministic, passes the contract test, and costs seconds per day.
